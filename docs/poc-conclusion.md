# 问启星河：提问驱动工作终端 POC 验证结论 v0.1

日期：2026-08-02  
对应 PRD：提问驱动创作平台 PRD v1.5  
交付形态：单个离线 HTML 文件

## 一、结论摘要

第一版技术 POC 成立：不用后端、框架或外部素材，也可以在一个 HTML 文件中完成“投出问题—四向重构—选择分支—形成问题谱系—生成阶段性成果—本地保存与导出”的最小闭环。银河粒子系统可以绑定真实界面状态，并提供低动态和静态降级，不必沦为与任务无关的加载动画。

这只能证明产品机制“可实现、可演示、可测试”，尚不能证明真实用户会持续使用，也不能证明规则式重构足以产生高质量洞见。下一阶段最重要的不是立即增加功能，而是让 5–8 名目标创作者实际完成一次任务，观察他们是否愿意采用系统建议的问题、能否更快形成成果，以及银河效果是否帮助理解状态。

## 二、已经验证的技术命题

### 1. 单文件离线闭环可行

最终 HTML 内联全部样式和脚本，不依赖 CDN、字体、图片、服务器或模型接口。自动化检查确认不存在 `fetch`、XHR、WebSocket 或外部 URL。用户双击文件即可运行。

### 2. “判断题 → 可探究问题”可先用透明规则验证

本地引擎能识别“是否、会不会、能不能”等封闭问法，并产生四个相互区分的方向：

- WHAT：定义概念与成功标准；
- WHY：寻找支持与反对机制；
- HOW：转成低成本、可逆的小实验；
- EVIDENCE：预先定义支持或推翻判断的证据。

规则输出始终标注为“本地 POC 建议”，没有伪装成事实答案或真实 AI 研究。

### 3. 问题谱系与成果谱系可以共用一个最小数据模型

原始问题、父子分支、当前问题、成果类型和事件日志被保存在同一个版本化会话对象中。Question Brief、研究计划、文章提纲和导出文件均能回溯到问题路径。这为后续知识图谱、智能体任务和 Obsidian 同步提供了可延伸的数据基础。

### 4. 银河可以表达真实状态

粒子系统绑定四个状态：待命、理解意图、展开路径、成果就绪。低动态模式取消高速变化，只保留静态构图、透明度与文字状态；Canvas 不承载关键业务信息，渲染失败不会阻断投问和导出。

### 5. 本地知识主权可以在第一版被用户感知

页面持续显示“本地模式”，支持保存、恢复、二次确认清除、Markdown 和 JSON 导出。存储容量不足或内容损坏时采用可恢复错误，不把当前会话锁死在产品中。

## 三、验证证据

- 20 项自动化测试通过：输入边界、封闭问题识别、四向重构、成果谱系、Markdown/JSON、不可变状态、本地存储异常、单文件构建、语义结构、低动态与隐私约束。
- 4 个 JavaScript 模块通过语法检查。
- 分发文件不包含外部脚本、样式、字体、图片或网络通信代码。
- 响应式样式明确覆盖主舞台 16:9、860px 和 540px 断点、最低 320px 宽度。
- 浏览器自动化环境因安全策略禁止访问本地文件和回环地址，因此本轮没有把“真实浏览器桌面/移动端截图”冒充为已完成证据；该项需要通过用户本机打开文件，或在获得正常 HTTPS 地址后补测。

## 四、仍未被验证的产品命题

1. 用户是否认为四向重构比普通聊天更有帮助。
2. 用户能否在 10 分钟内把模糊问题变成可执行计划。
3. 用户是否会主动选择分支，而不是期待系统直接给答案。
4. 银河粒子反馈是否提高理解与耐心，还是带来视觉干扰。
5. 用户是否重视 Markdown/JSON 所表达的知识主权。
6. 不同提问水平的用户是否需要不同引导密度。
7. 规则式引擎何时必须升级为带来源和评测的大模型系统。

## 五、建议的 5–8 人验证脚本

每位用户带来一个真实但尚未解决的问题，在不讲解功能的情况下完成以下任务：

1. 写下问题并投问。
2. 选择一个重构方向，说出选择原因。
3. 生成一种成果物并指出其中最有价值与最无价值的部分。
4. 下载 Markdown，说明是否愿意在自己的知识库继续使用。
5. 分别评价“问题更清楚了吗”“下一步更明确了吗”“银河帮助还是干扰”，采用 1–5 分和口述理由。

建议记录：首次投问时间、选择分支时间、成果生成率、导出率、建议采纳率、完成后的主观清晰度变化，以及用户主动关闭低动态模式的情况。不要把成交、停留时长或提问数量当作唯一成功指标。

## 六、下一版优先级

### P0：完成真实用户验证

- 补充 HTTPS 环境下的桌面与移动端浏览器检查。
- 访谈 5–8 名个人知识创作者。
- 对比“普通回答”与“四向重构”的建议采纳率和主观清晰度。

### P1：把规则 POC 升级为受控 AI

- 模型调用放在受控后端，禁止把 API 密钥写进 HTML。
- 输出采用结构化 Schema，并保留“建议—选择—修改”的用户控制权。
- 研究结果必须携带来源；证据、主张和推断分开存储。

### P2：扩大成果与记忆闭环

- 增加证据卡、主张卡、反例与事实核查。
- 接入 Obsidian 本地连接器和冲突副本策略。
- 在数据模型稳定后再接入真实多智能体编排。

## 七、最终判断

建议继续，但要坚持“先验证引导价值，再扩展 AI 能力”。当前 POC 已经足以用于第一次概念测试；如果目标用户不能明显感到问题变清楚，再多的智能体、知识图谱和粒子特效都不会解决核心价值问题。如果用户愿意采纳重构并带走成果，则可以进入联网研究与 Obsidian 连接器的第二阶段。

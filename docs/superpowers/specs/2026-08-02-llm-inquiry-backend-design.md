# 问启星河 LLM 探寻后端设计

状态：已由用户批准进入第一阶段实现。

## 目标

把 POC 中写死的提问分类和主动状态自报升级为服务端 LLM 分析：系统根据问题文本和最近上下文推断本轮认知与情绪状态，生成苏格拉底式反映、一个主追问和四条可选路径。DeepSeek 是首个供应商，但业务代码只依赖统一模型接口。

## 架构

前端继续构建为单 HTML；通过同源 `POST /api/v1/inquiry` 请求后端。后端使用 Fastify、TypeScript 与 Zod，密钥只读取 `DEEPSEEK_API_KEY`。DeepSeek 适配器请求 JSON Output，返回内容必须经过 Schema 校验；空内容、格式错误和远端错误最多重试一次，然后进入明确标注的本地降级。

接口以 SSE 返回 `status`、`result`、`done` 或 `error` 事件。服务端同时提供 `/` 静态单 HTML 和 `/api/v1/health`。开发会话写入 Node.js 内置 SQLite；只保存问题、结构化结果、供应商和时间，不保存隐藏推理。

## 状态模型

每轮结果包含：问题意图、问题形式、清晰度、假设、缺失维度；不确定性、紧迫度、行动感、情绪语气、置信度和原文证据；响应语气、难度、下一策略、意图反映、主追问和候选路径；安全标记。状态是本轮假设而不是人格或医学结论，低置信度必须使用保守措辞。

## 前端行为

删除启动前状态询问。HTTP 模式下投问触发真实 SSE：`queued → analyzing → guiding → ready`，并把结构化结果渲染到引导区；文件模式、后端不可用或模型降级时继续使用现有本地规则。结果区提供简短的“系统理解”及置信度，不显示隐藏推理。

## 隐私与故障

- API Key 不进入 HTML、日志、SQLite 或错误响应。
- DeepSeek `user_id` 使用随机会话标识，不含个人信息。
- 对模型响应执行严格 Schema 校验和长度限制。
- 429、超时、空 JSON、截断与无效 JSON 均返回可恢复错误并启用降级。
- 不进行疾病、人格或长期心理标签推断。

## 验收

- 无 API Key 时服务可启动，健康接口显示降级模式。
- 注入假模型时，SSE 顺序、结构化结果和 SQLite 记录可自动测试。
- DeepSeek 请求采用官方 OpenAI 兼容 `/chat/completions` 和 JSON Output。
- 前端不再要求用户先选择状态，且 file:// 仍可离线工作。
- 原有测试与新增服务端测试全部通过。

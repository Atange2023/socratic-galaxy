# 问启星河运行形态与版本边界

## 架构结论

问启星河不维护三套独立产品代码，而采用“一套思考内核、三种运行外壳”。网页负责客户可见的工作台与成果表达；LLM 负责理解、追问和结构化提炼；Skill 负责在 Agent 环境中复用同一套方法能力。

## 三种运行形态

| 形态 | 面向对象 | LLM 来源 | 数据位置 | 主要价值 |
| --- | --- | --- | --- | --- |
| Demo | 售前展示、内部评审 | 内置确定性示例 | 浏览器本地 | 无密钥、无网络也能稳定走完关键 USE CASE |
| Standalone | 企业家本人、试点客户 | 服务端 DeepSeek API | 浏览器本地；会话索引可存 SQLite | 任意真实问题都可获得动态分析，产品可独立交付 |
| Agent Skill | 已使用 Codex、GPTs、Gems 或企业 Agent 的团队 | 宿主 Agent 模型 | 宿主工作区、知识库或 Obsidian | 复用宿主的模型、检索、文件与多智能体能力 |

## 共用思考内核

三种形态必须共享：

- 六阶段工作流及状态迁移；
- 问题分析、状态假设、方法推荐、问题簇、研究问题和证据卡的数据协议；
- 苏格拉底式探寻、5-WHY、六顶思考帽等方法定义；
- 安全边界、用户校正机制、日志事件与成果物格式；
- 回归测试用例和客户演示黄金问题。

差异仅位于“模型适配器”和“存储/工具连接器”。Standalone 使用 DeepSeek provider；Agent Skill 使用宿主模型与工具；Demo 使用确定性 provider。

## DeepSeek 独立版的安全边界

1. API Key 只存在于服务端环境变量，不进入 HTML、浏览器存储、SQLite、日志或错误响应。
2. 前端只请求问启星河后端，不能从浏览器直接调用 DeepSeek。
3. 后端校验输入与模型 JSON 输出；超时或格式异常时降级到明确标注的 Demo 结果。
4. 正式客户部署需增加身份认证、租户隔离、限流、用量预算、审计与保留期限。
5. `.env` 已被 Git 忽略；`.env.example` 只能保留空值。

## 推荐发布节奏

- `0.3-demo`：当前可重复演示的黄金路径。
- `0.4-standalone`：接入真实 DeepSeek 密钥，完成动态提问分析与小范围试点。
- `0.5-skill`：抽取 provider-neutral 的 Skill 包，接入宿主 Agent 的检索与 Obsidian 能力。
- `1.0-pilot`：加入账号、权限、成本控制、真实文献检索与企业数据治理。

版本号代表能力成熟度，不复制前端。任何新方法和输出协议先进入共用内核，再由三种外壳调用。

# 提问驱动工作终端 POC 设计规格

日期：2026-08-02  
状态：已批准（采用单文件离线方案 A）  
依据：`outputs/提问驱动创作平台_PRD_v1.5.md`

## 1. 验证目标

本 POC 不证明完整商业价值，只验证三个可观察假设：

1. 用户能否把模糊、封闭或情绪化的问题，转化为可继续探究的问题分支。
2. 银河粒子动画能否表达真实工作状态，同时不妨碍阅读、输入和低动态用户。
3. 用户能否从一个问题形成最小成果物，并把数据以 Markdown/JSON 带走。

## 2. 产品边界

- 单个 HTML 文件交付，无服务器、无构建依赖、无外部字体或素材。
- 本地规则式引导，不冒充联网 AI、事实研究或心理诊断。
- 数据默认只保存在浏览器 `localStorage`；支持下载 Obsidian 兼容 Markdown 与 JSON。
- 第一版不实现联网检索、真实多智能体、双向 Obsidian 同步、自动发布或账号系统。

## 3. 信息架构与核心流程

桌面采用 16:9 工作台：左侧为项目轨道，中间为投问与引导工作区，右侧为状态和成果区。窄屏按“投问—引导—成果—历史”顺序单列重排。

核心流程：

`输入问题 → 可选状态自报 → 投问 → 系统反映意图 → 展示 WHAT/WHY/HOW/证据 四个重构方向 → 用户选择分支 → 形成问题树 → 生成 Question Brief / 研究计划 / 文章提纲 → 本地保存或导出`

每轮只突出一个主追问；并列方向作为可选择的卡片，而不是连续盘问。

## 4. 视觉与动效

- 风格：深空编辑舱；墨蓝黑背景、低饱和蓝紫星云、暖金作为行动色、青绿作为完成色。
- 字号：品牌标题使用 `clamp(1.25rem, 2vw, 1.85rem)`，主问题不超过 `2rem`，正文行高不低于 `1.65`。
- 密度：卡片间距 16–24px，正文单行建议 32–48 个中文字符；不采用大面积巨型标题。
- 银河 Canvas 对应四种真实状态：`idle` 正面星云、`reflecting` 翻转收束、`branching` 多路径风暴、`ready` 星座稳定。
- `prefers-reduced-motion` 或用户手动开启低动态时，取消翻转和高速粒子，仅用透明度、状态文字和进度节点反馈。
- Canvas 不承载关键信息；动画失败时页面全部功能仍可使用。

## 5. 组件

1. `GalaxyCanvas`：粒子渲染、状态机、帧率降级和尺寸自适应。
2. `QuestionComposer`：问题输入、示例、状态自报、长度与空值校验。
3. `GuidancePanel`：意图反映、四向重构、一个主追问与分支选择。
4. `QuestionTrail`：展示问题谱系和当前分支，不输出羞辱性能力评分。
5. `ArtifactStudio`：生成并编辑三类最小成果物。
6. `LocalVault`：本地保存、恢复、清除、Markdown/JSON 下载。
7. `PocMeter`：仅记录本机事件，显示闭环是否走通，不上传数据。

## 6. 数据结构

```js
{
  schemaVersion: 1,
  project: { id, title, createdAt, updatedAt },
  selfReport: { state: 'calm|uncertain|energized|stuck|none' },
  questions: [{ id, parentId, text, lens, createdAt }],
  activeQuestionId: string,
  artifact: { type, title, markdown, updatedAt },
  events: [{ type, at, meta }],
  settings: { reducedMotion, sound: false }
}
```

状态变更先写入内存，再尝试持久化；持久化失败只提示，不中断当前会话。

## 7. 引导规则

- 识别“是否/会不会/能不能”等封闭问法，分别生成定义、机制、路径与证据方向。
- 识别过短或边界模糊的问题，补充对象、时间范围、目标和判断标准。
- 回应模板先承接用户意图，再给选择权，不使用“你的问题质量低”等评判。
- 情绪只读取用户主动选择的当下状态；不根据措辞推断疾病、人格或根因。
- 规则输出始终标注为“本地 POC 建议”，防止与事实答案混淆。

## 8. 错误与降级

- 空输入：聚焦输入框并说明需要一个想探索的问题。
- 超长输入：保留内容并提示缩短到 500 字以内，不静默截断。
- 存储不可用：切换为临时会话，仍支持下载导出。
- Canvas 不可用：隐藏画布，保留文本状态条。
- 下载不支持：显示可复制的 Markdown。
- JavaScript 禁用：`noscript` 给出明确说明。

## 9. 测试设计

- Node 内置测试覆盖：输入规范化、封闭问题识别、四向重构、成熟度信号、成果物生成、Markdown/JSON 序列化和存储失败降级。
- 浏览器烟雾测试覆盖：首屏无横向溢出、投问主路径、选择分支、生成成果、导出、清除数据、低动态切换。
- 视觉检查尺寸：1440×810（主效果 16:9）、390×844（移动端）。
- 无障碍检查：键盘可达、可见焦点、ARIA 状态、颜色对比、低动态模式。

## 10. POC 成功标准

- 首次打开无需安装即可运行。
- 用户可在三分钟内完成“投问—选分支—生成成果—导出”。
- 动画和数据状态同步，不展示假进度。
- 1440×810 与 390×844 均无关键内容遮挡或横向滚动。
- 所有自动化测试通过，控制台无未处理异常。
- 结论报告明确区分技术验证结果与待真实用户验证的产品假设。

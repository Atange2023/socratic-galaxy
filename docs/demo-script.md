# 问启星河 · 潜在客户演示脚本

## 启动

```powershell
npm install
npm run demo
```

打开终端显示的本地地址。无需 DeepSeek API Key；无密钥时顶部显示“演示引擎”。

## 15 分钟黄金路径

### 1. 放下问题

输入：

> 公司最近增长慢，是不是团队执行力不行？

点击“开始梳理”。说明：系统首先保留“我的原话”，不会用学术表达覆盖它。

### 2. 看清问题

展示四行 AI 暂定理解：现象、当前解释、未知和语气假设。强调每项都可修正。

在主问题中输入：

> 销售机会到签约的转化率连续两个季度下降。

点击“形成问题底稿”。

### 3. 选择练习

展示为什么先推荐“苏格拉底式澄清”、预计 8 分钟以及会得到什么。点击“开始这项练习”。

### 4. 完成四轮澄清

依次输入：

1. 目前只是销售总监和管理层的感觉，还没有拆销售漏斗数据。
2. 我说的执行力，主要是销售和产品跨部门协作不顺畅。
3. 有的团队动作很快，但转化也没有明显提升。
4. 如果客户预算整体收缩，这个判断可能不成立。

每轮指向右栏，说明系统把观察、判断和证据需求分开保存。完成后点击“加入问题地图”。

### 5. 选择问题簇主线

在“跨部门目标一致性可能影响销售机会推进”节点点击“设为主线”。说明其他分支没有删除。

展示经营语言到构念候选的对应关系，以及所有构念的“待核验”状态。

在研究问题候选中选择“关系 / 机制型”，点击“去核验证据”。也可演示过程型候选，说明系统不强迫所有问题变量化。

### 6. 查看证据状态

展示：

- 每条来源都可以打开；
- “已读页面、摘要层、仅元数据”明确区分；
- Crossref 仅元数据不能支持原文或因果结论；
- 页面明确写着“预置演示来源，不是实时全网检索”。

点击“我已查看证据状态”，再点击“生成阶段成果”。

### 7. 带走成果

展示阶段研究简报：原话、问题变化、研究问题、构念、证据缺口、来源和下一步数据行动。

选择用途“下周继续研究 / 管理团队讨论 / 导师评审”，然后导出 Markdown。

刷新页面，展示会话能够从本地恢复。

## 当前真实能力

- 六阶段工作流和本地持久化；
- 问题理解的可校正结构；
- DeepSeek 服务端适配、Schema 校验、SSE 与降级；
- 苏格拉底四回合练习；
- 问题簇、研究主线、构念候选与两类研究问题；
- 带读取深度的可核验预置来源；
- 研究简报和 Obsidian Markdown 导出；
- 响应式银河工作台。

## 当前演示能力

- 方法推荐与练习内容使用确定性的演示协议保障演示稳定；
- 证据室使用预置权威来源，不是本轮实时检索；
- 构念和关系只作为待核验候选，不宣称已有因果证明；
- “DBA 级”是后续质量门，不是当前自动保证。

## 下一次集成

- OpenAlex/Crossref 实时查询与 DOI 去重；
- 文献摘要/全文读取权限和证据定位；
- 更多方法协议及授权审查；
- Obsidian 增量导出与企业私有资料连接器。

## API 异常时的话术

> 当前 DeepSeek 没有配置或暂时不可用，系统已切换到明确标注的演示引擎。用户输入和已形成的路径不会丢失；产品正式版也会采用相同的可恢复设计。
